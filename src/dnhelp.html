Глава I. Общие положения

Система ДекаNET™ разработана для решения проблемы автоматизации организационной деятельности деканатов высших и средних специальных учебных заведений и представляет собой распределенную автоматизированную многопользовательскую систему учета академической успеваемости и управления контингентом студентов.

В функциях системы ДекаNET™ сделана попытка автоматизировать наиболее трудоемкие и рутинные операции в деканате. В системе учтен более чем десятилетний опыт эксплуатации подобных систем автоматизации.

Раздел I.1 Технология

Система ДекаNET™ использует трех уровневую технологию доступа к данным: WEB-клиент - WEB-сервер - Сервер баз данных, обеспечивающую эффективную управляемость, централизацию и защиту информации. Система построена на open source программных продуктах, и обеспечивает минимизацию дополнительных затрат на системные программные платформы, масштабируемость, открытость для модификации и тонкой настройки.

Актуальная версия ДекаNET™ построена на следующей связке open source продуктов: Браузер - Apache - PHP5 - MySQL5. Все компоненты имеют соответствующие версии под ОС Linux и Windows семейств, поэтому можно охарактеризовать систему ДекаNET™ как платформонезависимую.

Раздел I.2 Интерфейс пользователя

ДекаNET™ - это типичное Web-приложение. Пользователь получает доступ к данным при помощи Интернет-браузера.

Как и в любом Web-приложении, основным приемом работы является переход по ссылкам. Кроме этого, при заполнении форм, пользователь осуществляет выбор величин из списков и ввод значений в поля. Интуитивная прозрачность Web-интерфейса создает условия для эффективного и быстрого освоения пользователем приемов эксплуатации системы.

Верхняя панель страницы системы отображает выбранную (текущую) иерархию объектов.

Левая вертикальная панель страницы системы отображает постоянный список команд основного меню, и, при необходимости, контекстный список команд опций.

Раздел I.3 Отчётность

Команда опций, заключённая в двойные кавычки, вызывает формирование соответствующего отчёта. При вызове команды, отчет формируется как отдельная HTML-страница, не может быть отредактирован, но может быть распечатан средствами Браузера.

Команды-отчёты снабжены пиктограммой экспорта в офисное приложение. При неполном соответствии отчета требуемой форме, перед печатью твердой копии документа, пользователь имеет возможность внести необходимые исправления.

Раздел I.4 Иерархия объектов

Работа в ДекаNET™ строится на основе выбора объекта из иерархии Страна>Регион>Город>ВУЗ>Факультет>Отделение>Учебная группа>Студент

Добавление ВУЗов и Факультетов производится системным программистом ДекаNET™. Добавление отделений, учебных групп и студентов производится непосредственно пользователями ДекаNET™, имеющими соответвующие права.

Практически все операции в системе производятся над текущим объектом. Набор доступных операций динамически изменяется, в зависимости от уровня иерархии объекта.

Дочерний объект иерархии выбирается из списка-состава, выводимого при выборе родительского объекта. Отображаемые в списках объекты, снабжаются пиктограммой Удалить при необходимости обеспечить возможность удаления выбранного объекта.

Раздел I.5 Система разграничения доступа к данным

Пользователям ДекаNET™ назначаются роли, определяющие набор разрешенных операций в системе. Роль [Администратор] предназначена для управления пользователями, администраторам разрешен только просмотр данных объектов.

Роли [Декан] и [Зам. декана] имеют доступ ко всем (в том числе критическим) операциям над объектами. Роль [Секретарь] имеет доступ к основным рутинным операциям над объектами. Роли [Ревизор] разрешен только просмотр данных.

Кроме того, каждому пользователю администратором ограничивается набор объектов, доступных из иерархии объектов.

Рекомендуется включение администратором ДекаNET™ двухфакторной аутентификации пользователей в целях предотвращения несанкционированного доступа. Через 10 минут (время может быть изменено системным программистом) бездействия пользователя его текущая регистрация в системе прекращается.

Глава II. Контингентные операции

ДекаNET™ обеспечивает возможность зачисления, отчисления и перевода студентов по отделениям факультетов. Эти изменения контингентного статуса студента производятся на основе формируемого в момент операции приказа по личному составу.

Без фиксации в приказе по личному составу, производится перевод студента из одной учебной группы в другую, но только в пределах одного отделения и потока.

Раздел II.1 Приказы по личному составу

Приказ по личному составу (далее приказ по л/с) имеет следующие атрибуты:

1. Состояние приказа (Проект/Завершён);
2. Дата издания;
3. Дата завершения (подписи);
4. Номер по делопроизводству;
5. Перечень включенных в приказ студентов, с указанием даты и контингентной операции для каждого студента.

Производство контингентной операции всегда начинается с создания нового (или выбора существующего) проекта приказа по л/с.
При этом доступны вкладки:
последний - где отображается последний приказ по л/с выбранный в ходе текущего сеанса работы с системой;
за месяц - где отображается список проектов приказов по л/с, созданных и незавершенных за последний месяц;
все - где отображается список всех проектов приказов по л/с.

Далее производится выбор существующего проекта приказа, или создается новый командой опций +приказ. При создании нового проекта приказа по л/с ДекаNET™ предлагает заполнить необязательные наименование и примечание документа. Созданному проекту приказа по л/с автоматически присваивается следующий по порядку номер, который может быть изменен при завершении производства по документу.

Обычно, следующим шагом, осуществляется выбор контингентной даты и операции для выбранного одного или нескольких студентов, включаемых в приказ (см. описание конкретной контингентной операции).

Ссылку на приказ по л/с можно получить на вкладках контингент или документы при выбранном студенте, а так же через команды основного меню Документы (для незавершенных производством документов) и Поиск/документа.

При переходе по ссылке приказа по л/с отображается экранная форма приказа, содержащая атрибуты приказа и список включенных в приказ студентов, сгруппированный по контингентной операции.

Изменение атрибутов приказа по л/с возможно только в состоянии проекта. Поэтому для завершенного производством приказа предоставляется команда опций В проект. Для проекта приказа по л/с предоставляются операции Удалить (удаление проекта приказа) и Завершить (завершение производства по документу с вводом даты подписания приказа и действительного номера по делопроизводству). В списке включенных в проект приказа студентов, на дате контингентной операции, располагается ссылка для изменения контингентной даты и операции по каждому студенту.

Студенты, включенные в проект приказа, сохраняют свой предыдущий контингентный статус до момента завершения производства по приказу.

Раздел II.2 Поиск студентов и документов, корзина

Команда основного меню Поиск обеспечивает доступ к трём вкладкам Поиск студента, контингента и документа.

Поиск студента осуществляется через ввод одного или нескольких параметров поиска из набора, размещенного на вкладке. Студент может отображаться в списке найденных несколько раз, если обучается (обучался) на двух и более отделениях. Найденные студенты отображаются в виде списка, в котором имя студента является ссылкой для выбора этого студента в качестве текущего.

Каждая строка списка найденных студентов завершается флажком В корзину. Отмеченных флажком студентов можно добавить в корзину системы для производства контингентных операций над несколькими студентами одновременно. Собственно помещение отмеченных студентов в корзину, производится кнопкой В корзину, расположенной в заголовке списка найденных студентов. Добавление студентов в корзину возможно в несколько приемов поиска.

Текущее содержимое корзины доступно через команду основного меню Корзина(10). Цифра в наименовании этой команды показывает текущее количество студентов в корзине.

Здесь же доступны команды опций: Сброс - для очистки корзины, Зачислить, Отчислить и Группа.

Поиск контингента - это поиск студентов и соответствующих приказов по л/с по контингентной операции и периоду ее проведения.

Поиск документов осуществляется через ввод одного или нескольких параметров поиска из набора, размещенного на вкладке.
Работа корзины с контингентом и документами не предусмотрена.

Раздел II.3 Создание учебной группы

При выбранном отделении на вкладке состав отображается список учебных групп отделения.

В опциях доступна команда +группу для создания новой учебной группы студентов.
В качестве атрибутов создаваемой группы вводятся:
Индекс - для формирования имени учебной группы,
Год поступления - для определения потока создаваемой учебной группы,
Необязательное Примечание.

Конечное наименование группы строится системой автоматически на основе выбранной маски.
Если маска задана как {Аббревиатура факультета}-{Курс}{Индекс}, то наименование группы формируется как "ФИЗ-12". Маска построения наименования группы, является атрибутом отделения и может быть изменена.

Только что созданная учебная группа, определяется системой как неактивная (выпущенная), до момента, когда в ходе операций +студент, Восстановить, Зачислить или Группа, в ней появится хоть один активный по контингентному статусу студент. И наоборот, любая учебная группа определится системой как неактивная (выпущенная), как только все студенты из ее состава будут выпущены или отчислены.

Раздел II.4 Зачисление нового студента

При выбранной учебной группе на вкладке состав отображается список студентов группы.

В опциях доступна команда +студент для зачисления в учебную группу нового студента.

После создания/выбора проекта приказа по л/с отображается форма для ввода данных студента, все поля которой обязательны для заполнения. Если поле Личный № останется незаполненным, то система присвоит его автоматически.

Новый студент, включенный в приказ по л/с, определяется системой как неактивный (отчисленный), до завершения производства по приказу.

Раздел II.5 Назначение старосты учебной группы

При выбранном студенте на вкладке Контингент в опциях доступна команда Староста, вызов которой, назначает текущего студента старостой учебной группы.

Признак старосты выводится как примечание в "Протоколе заседания стипендиальной комиссии" и может быть использован в принятии решения при начислении стипендии.

Раздел II.6 Отчисление студентов

При выбранном студенте на вкладке Контингент в опциях доступна команда В приказ.

После создания/выбора проекта приказа по л/с необходимо выбрать Причину (контингентный статус) и дату контингентной операции.

Отчисляемый студент, включенный в приказ по л/с, продолжает определяться системой как активный, до завершения производства по приказу.

Возможно отчисление уже неакивного студента, в целях изменения его контингентного статуса.

Отчисление нескольких студентов одновременно, осуществляется через корзину.
В режиме просмотра содержимого корзины в опциях доступна команда В приказ, а дальнейшая процедура отчисления аналогична отчислению студента, производимому в индивидуальном порядке. При заполнении формы с причиной и датой отчисления доступен флаг Сбросить корзину, при его установке, после включения студентов корзины в проект приказа по л/с, содержимое корзины удаляется.

Раздел II.7 Восстановление ранее отчисленных студентов

При выбранной группе, ранее отчисленные студенты отображаются на владке Состав/Отчисленные. Доступ к отчисленному студенту возможен так же через Поиск/студента.

При выбранном студенте на вкладке Контингент в опциях доступна команда Восстановить.

После создания/выбора проекта приказа по л/с производится выбор учебной группы, в которую восстанавливается студент, далее выбирается Причина (контингентный статус) и дата восстановления.

Восстанавливаемый студент, включенный в приказ по л/с, продолжает определяться системой как не активный, до завершения производства по приказу.

Индивидуальный учебный план восстанавливаемого студента, автоматически согласуется с программой отделения и потока, на которые производится восстановление.

Восстановление нескольких студентов одновременно (через корзину) не предусмотрено.

Раздел II.8 Зачисление студентов на другое отделение

Если восстановление студента перемещает студента из учебной группы, где он находился как отчисленный, для возобновления обучения в новой группе (возможно на другом отделении и потоке), то зачисление студентов на другое отделение, позволяет организовать параллельное обучение студентов на нескольких отделениях, либо продолжение обучения на другом отделении, по завершении обучения на первом (например, из абитуриентов в студенты или из бакалавриата в магистратуру) с сохранением данных предыдущего обучения.

Зачисление студентов на другое отделение производится только через корзину.

При этом учебная группа, куда зачисляются студенты, должна быть текущей (выбрана).

В режиме просмотра содержимого корзины в опциях доступна команда Зачислить.

После создания/выбора проекта приказа по л/с, выбирается Причина (контингентный статус) и дата зачисления. При заполнении формы с причиной и датой зачисления доступен флаг Сбросить корзину, при его установке, после включения студентов корзины в проект приказа по л/с, содержимое корзины удаляется.

Зачисленные в текущую группу студенты, включаются в проект приказа по л/с и определяются системой как не активные, до завершения производства по приказу.

Раздел II.9 Перевод студента в другую учебную группу

Перевод студента в другую учебную группу, осуществляется только в группы этого же потока на отделении. При этом операция не фиксируется в приказе по л/с.

При выбранном активном по контингентному статусу студенте, на вкладке Контингент в опциях доступна команда Группа.

Далее отображается список учебных групп того же потока на отделении. Выбор новой учебной группы перемещает в нее студента.

Перевод в другую учебную группу нескольких студентов одновременно, осуществляется через корзину.
В режиме просмотра содержимого корзины в опциях доступна команда Группа, а дальнейшая процедура перевода аналогична переводу в другую учебную группу студента, производимому в индивидуальном порядке.

Если корзина содержит студентов из разных потоков, операция перевода в другую учебную группу отменяется.

Раздел II.10 Перевод студентов на следующий курс

При выбранном отделении на вкладке Состав в опциях доступна команда След. курс.

Все студенты отделения с активным контингентным статусом, обучающиеся на невыпускных курсах, автоматически включаются в проект приказа по л/с с контингентным статусом перевод на следующий курс.

После создания/выбора проекта приказа по л/с необходимо ввести дату перевода.

При включении студентов проект приказа по л/с анализ успеваемости студентов не производится. Это позволяет деканату производить "условный перевод на следующий курс" для студентов, имеющих академические задолженности. Перед операцией перевода на следующий курс студенты, подлежащие отчислению, должны быть отчислены, и производство по соответствующим приказам по л/с завершено.

Операция перевода на следующий курс не изменяет текущего контингентного статуса студентов. ДекаNET™ будет определять студента на следующем курсе лишь после календарного наступления нового учебного года. Факт составления приказа по л/с о переводе на следующий курс учитывается при составлении "Сводки движения контингента студентов".

Раздел II.11 Отчисление выпускников

При выбранном отделении на вкладке остав в опциях доступна команда Выпуск.

Все студенты отделения с активным контингентным статусом, обучающиеся на выпускном курсе, автоматически включаются в проект приказа по л/с с контингентным статусом выпуск по завершении обучения.

После создания/выбора проекта приказа по л/с необходимо ввести дату выпуска.

При включении студентов проект приказа по л/с анализ успеваемости студентов не производится. Перед операцией выпуска студенты, подлежащие отчислению, должны быть отчислены, и производство по соответствующим приказам по л/с завершено.

Включенные в проект приказа по л/с выпускаемые студенты, определяются системой как активные, до завершения производства по приказу.

Раздел II.12 Списки, справки и сводки по контингенту студентов

При выбранном факультете в меню опций доступна команда Контингент, формирующая "Cводку движения контингента студентов" за выбранный месяц. Данные отчета сгруппированы по отделениям, курсам и типам контингентных операций. Рассчитываются соответствующие количества женщин, мужчин и обучающихся на внебюджетной основе.

При выбранной учебной группе в меню опций доступны команды Список 1, Список 2 и Список 3, формирующие списки состава выбранной учебной группы с различными данными. В списки включаются студенты, в зависимости от выбранной вкладки Состав/активные/отчисленные/все. Команда опций БланкВед позволяет сформировать бланк экзаменационной ведомости на учебную группу без регистрации в системе. Ввод результатов со сформированной таким образом ведомости не возможен.

При выбранном студенте на вкладке Личное в меню опций доступны команды Справка и Справка в ПФ, формирующие и регистрирующие в системе соответствующие учебные справки для студента.

Глава III. Учёт академической успеваемости

Раздел III.1 Государственные образовательные стандарты

Государственный образовательный стандарт является атрибутом отделения и содержит данные по составу и объему основных разделов дисциплин направления подготовки по специальности.

Компоненты, циклы, разделы дисциплин, их коды и объемы в академических часах, определяются официально опубликованным документом государственного образовательного стандарта и вводятся в систему в период первичной настройки и создания отделений факультета.

Пользовательского интерфейса для создания государственных стандартов не предусмотрено.

Состав раздела дисциплин определяется факультетом и может варьироваться для каждого учебного заведения в пределах, ограниченных государственным образовательным стандартом. Перед началом составления учебной программы отделения необходимо определить конкретный состав дисциплин в разделе.

При выбранном отделении на вкладке программа доступна команда опций Стандарт, отображающая разделы дисциплин соответствующего государственного образовательного стандарта.

На коде каждого раздела расположена ссылка для отображения состава выбранного раздела дисциплин. При выбранном разделе дисциплин в доступна команда опций +дисциплину. Добавляемая в раздел дисциплина выбирается из общего справочника дисциплин системы, снабженного инструментом поиска. Общий справочник дисциплин имеет команду опций Новая дисц. для создания дисциплины при ее отсутствии.

При добавлении дисциплины в раздел, система присваивает ей следующий по порядку код, который можно изменить по ссылке на нём.

В дальнейшем, при составлении учебной программы отделения выбор дисциплин осуществляется только из состава включенных в стандарт.

Раздел III.2 Учебная программа отделения

При выбранном отделении на вкладке программа отображается учебная программа отделения.

Учебная программа составляется для каждого потока отделения. В строке Поток: отображается выбранный поток, предоставляется список потоков и команда Выбор для перехода к учебной программе выбранного потока отделения.

Для обеспечения возможности выбора потоков завершивших обучение, необходимо при выбранном отделении на вкладке состав перейти в режим выпущенные или все.

Удаление пункта учебной программы отделения возможно при отсутствии оценок в соответствующих индивидуальных учебных планах студентов.

Состав программы отображается по семестрам. В строке Семестр: размещены ссылки для перехода по семестрам, и поле Кол-во семестров: для установки общего количества семестров текущего потока отделения.

В целях обеспечения календарного контроля академической успеваемости студентов в строке Сессия: предоставляется возможность установить сроки начала и окончания соответствующей экзаменационной сессии текущего потока отделения.

При выбранном потоке и семестре доступна команда опций +пункт, позволяющая выбрать дисциплину из состава включенных в раздел государственного образовательного стандарта, и задать вид контроля и объем в академических часах. Флаг Скрыть используется для исключения пункта программы из документов по академической успеваемости студента (академической справки, учебной карточки и выписки к диплому). Это позволяет включать в программу промежуточные аттестации и пр., обычно не учитывающиеся в итоговых документах по академической успеваемости.

Новый пункт программы автоматически добавляется в индивидуальные учебные планы всех студентов данного потока с активным контингентным статусом.

Каждый пункт программы отделения это ссылка на форму, для изменения вида контроля, объема и признака скрытия. Здесь же доступны команды опций +выбор - позволяющая создать набор дисциплин для выбора и "Должники" - для регистрации и формирования экзаменационой ведомости должников потока по данному контрольному мероприятию.

Поддержка наборов дисциплин для выбора позволяет включать в программу отделения пункты, содержащие несколько дисциплин одинакового вида контроля и объема. При формировании индивидуального учебных плана студента выбирается одна дисциплина из набора.

Раздел III.3 Индивидуальный учебный план студента

При выбранном студенте на вкладке успеваемость отображается индивидуальный учебный план студента. Состав индивидуального учебного плана формируется как подмножество пунктов учебной программы отделения.

Удаление пункта индивидуального учебного плана возможно при отсутствии оценки по этому пункту.

Список пунктов индивидуального учебного плана студента отображается по семестрам и содержит результаты сдачи студентом контрольных мероприятий, с указанием дисциплины, маркера набора, вида контроля, объема и оценки с номером академического документа (экзаменационного листа, ведомости, протокола ГЭК).

В меню опций доступны команды Синхро - для синхронизации индивидуального плана с программой отделения, "Титул" - для формирования титульного листа учебной карточки, "Карточка" - для формирования листов академической успеваемости учебной карточки и "Копия АС" - для регистрации и формирования копии академической справки для студента.

В столбце Выбор, в случае, если программа отделения предусматривает набор дисциплин, расположен маркер, позволяющий произвести выбор дисциплины.

На номере академического документа располагается ссылка, отображающая форму соответствующего экзаменационного листа, ведомости или протокола ГЭК. В опциях доступна команда "Документ", для формирования печатного вида документа. Если документ уже введен, в опциях доступна команда Реввод для исправления неверно введенных результатов. Если документ не введен, то предоставляется возможность ввода, а в меню опций доступна команда Удалить.

При ревводе экзаменационного листа (команда Реввод) предоставляется возможность ввода пустой оценки, после чего экзаменационный лист приобретает статус не введенного и может быть удален.

Ввод результатов с академических документов производится так же командой основного меню Ввод оценки. Здесь возможно использование сканера штрих-кода.

ДекаNET™ поддерживает хранение данных по всем попыткам сдачи студентом контрольного мероприятия. В строке Результаты: ссылками последние и все производится переключение отображения только последних (по дате) или всех результатов, соответственно.

В строке Продление: задается причина и срок продления сессии выбранного семестра. Продление сессии учитывается в "Протоколе заседания стипендиальной комисии" и "Итогах сессии".

На наименовании дисциплины расположена ссылка на форму, отображающую все академические документы, сформированные для студента, по данному пункту индивидуального плана, включая те, по которым результата не получено, а так же позволяющую изменить объем дисциплины для выбранного студента.

Здесь же доступна команда опций "Лист", регистрирующая и формирующая новый экзаменационный лист. В случае, когда текущий пункт индивидуального плана является выпускным мероприятием (государственным экзаменом, защитой дипломного проекта или работы) эта команда формирует Протокол ГЭК, имеющий то же назначение, что и экзаменационный лист.

Раздел III.4 Академическая успеваемость учебной группы

При выбранной учебной группе на вкладке успеваемость отображается список пунктов программы отделения с указанием экзаменационых ведомостей, выданных для учебной группы.

На номере ведомости располагается ссылка для работы с академическим документом.

В опциях доступны команды "Сводка" - для печати "Cводки результатов сессии" для учебной группы и "Протокол" - для формирования "Протокола заседания стипендиальной комиссии".

На наименовании дисциплины расположена ссылка на форму, отображающую результаты сдачи данного контрольного мероприятия студентами группы. Здесь доступны команды опций "Ведомость" - регистрирующая и формирующая новую экзаменационную ведомость и "Успеваемость" - для печати результатов сдачи данного контрольного мероприятия студентами группы. В случае, если вид контроля по выбранной дисциплине подразумевает хранение темы индивидуальной работы (например, темы курсового проекта), то дополнительно доступны команды опций "Ведомость тем" - регистрирующая и формирующая новую ведомость тем индивидуальных работ и "Темы" - для печати тем индивидуальных работ. Ввод данных с ведомости тем производится аналогично вводу результатов с экзаменационной ведомости.
